## 0. Словарь: 15 слов, без которых непонятно всё остальное

| Слово | Что это простыми словами |
|---|---|
| **Frontend / интерфейс** | То, что видно в браузере: кнопки, таблицы, экраны. У нас их два: Teacher Portal и My DU. |
| **Backend / сервер** | То, что хранит данные и решает, кому что можно. У нас это **Firebase** (своего сервера нет). |
| **Firebase** | Набор облачных сервисов Google. Мы используем три: Auth, Firestore, Hosting. |
| **Firebase Auth** | Сервис входа. Проверяет почту и пароль и выдаёт пользователю «пропуск» (токен) с его ID (`uid`). |
| **Cloud Firestore** | Облачная база данных. Не таблицы SQL, а **коллекции документов** (похоже на папки с JSON-файлами). |
| **Firebase Hosting** | Хранит готовые файлы сайта и раздаёт их по ссылке `https://…web.app` с HTTPS. |
| **Security Rules** | Файл правил `firestore/firestore.rules`. Firestore проверяет по нему **каждый** запрос: можно читать/писать или нет. Это и есть наш «бэкенд». |
| **SDK** | Библиотека `firebase` внутри нашего JS-кода. Через неё интерфейс сам ходит в Auth и Firestore. |
| **React** | Библиотека, на которой написаны экраны (компоненты). |
| **TypeScript (TS)** | JavaScript с типами: ловит ошибки до запуска. |
| **Vite** | Инструмент, который запускает сайт локально (`npm run dev:…`) и собирает его для публикации (`npm run build`). |
| **npm** | Менеджер пакетов Node.js: ставит библиотеки (`npm install`) и запускает команды (`npm run …`). |
| **Seed** | Скрипт, который заполняет базу демо-данными (группы, студенты, оценки). |
| **Deploy** | Публикация: залить правила в Firestore и сайт на Hosting. Команда `npm run deploy`. |
| **Real-time (onSnapshot)** | Подписка на данные: база сама присылает изменения, экран обновляется без перезагрузки. |

## 1. Проект в одном абзаце

Студенты AITU часто узнают, что **не допущены к файналу** или **теряют стипендию**, когда исправлять уже поздно (в опросе Stage 1: 9 из 13 замечали риск слишком поздно). **Student Success Radar** — это система раннего предупреждения:

* **преподаватель** в **Teacher Portal** (симулятор LMS) отмечает посещаемость и ставит оценки;
* **студент** в приложении **My DU** (реплика официального приложения) видит по каждому курсу **уровень риска**, **причины** и **конкретные действия** с числами («наберите в Register Endterm не меньше 69»).

Расчёт сделан **по правилам AITU**: регистры, допуск к файналу, Total, FX/F, порог стипендии 70 %.

|---|---|---|---|
| **Студент** | My DU (`/my-du/`) | Вступает в курсы по коду, отмечается по QR у двери, видит **только свои** опубликованные данные, риск и «План на неделю» | **Регистрируется сам** (корпоративная почта, подтверждение почты) или создаётся seed |

### Как считается риск (уровни)

| Уровень | Когда |
|---|---|
| 🔴 **Высокий риск** | ≥ 2 причины **или** одна причина «допуск к файналу под угрозой» |
| 🟡 **Внимание** | Ровно 1 причина |
| 🟢 **В норме** | Причин нет **и** данных достаточно (≥ 2 источника: посещаемость, сдача работ, оценки) |
| ⚪ **Мало данных** | Данных недостаточно — система **не делает вид**, что всё хорошо |

Причины (сигналы):

| Код | Условие (демо-политика + правила AITU) | Рекомендации |
|---|---|---|
| `ATTENDANCE_LOW` | Посещаемость < 80 % | Проверить посещаемость, написать преподавателю |
| `OVERDUE_WORK` | ≥ 2 несданных работ после дедлайна | Сдать долги, составить план |
| `ADMISSION_RISK` | RegMid < 25, RegEnd < 25 или RegTerm < 50 (с учётом того, что ещё можно набрать) | Поднять регистр (сколько нужно), написать преподавателю |
| `SCHOLARSHIP_RISK` | Курс ниже 70 % (GPA < 2.33) | Защитить стипендию (сколько нужно), разобрать слабые работы |
| `RECENT_GRADES_LOW` | Только для курсов без регистров: последние оценки < 60 % | Разобрать слабые работы |

### Правила AITU, которые зашиты в расчёт

```
RegTerm = 0.5 · RegMid + 0.5 · RegEnd
Допуск к файналу: RegMid ≥ 25 И RegEnd ≥ 25 И RegTerm ≥ 50, иначе F (летний семестр)
Total   = 0.3 · RegMid + 0.3 · RegEnd + 0.4 · Final      (пример: 80 / 86 / 70 → 77.8)
Final 25–49 → FX (платная пересдача),  Final < 25 → F
Стипендия: по каждому курсу ≥ 70 % (GPA 2.33); комфортно ≥ 80 % (GPA 3.0)
```

Три принципа честности: **не проверено ≠ 0 баллов**, **не отмечен ≠ пропуск**, **мало данных ≠ «в норме»**.

## 5. Архитектура: как всё связано

### 5.1 Общая схема

```
┌─────────────────────┐        ┌──────────────────────┐
│  Teacher Portal      │        │  My DU (студент)      │
│  React + TypeScript  │        │  React                │
│  https://…web.app/   │        │  https://…web.app/my-du/
└──────────┬───────────┘        └──────────┬───────────┘
           │   общий код: @aitu/domain (расчёт риска) + @aitu/data (работа с базой)
           │                               │
           │ 1) вход → токен               │
           ▼                               ▼
     ┌──────────────── Firebase (Google Cloud) ────────────────┐
     │  Auth  ──►  «это uid demo-teacher-math»                  │
     │                                                           │
     │  Firestore  ◄── каждый запрос проходит Security Rules ──  │
     │     offerings / sessions / attendanceRecords /            │
     │     assessments / assessmentRecords / audit / users       │
     │                                                           │
     │  Hosting  ── раздаёт файлы сайта (HTML/JS/CSS/картинки)   │
     └───────────────────────────────────────────────────────────┘
```

**Своего сервера нет.** Это называется **BaaS (Backend as a Service)**: хранение, вход и проверку прав делает Firebase, а логика «кому что можно» записана в Security Rules.

### 5.2 Что происходит, когда преподаватель публикует оценку (по шагам)

1. Преподаватель открывает `https://…web.app` → **Hosting** отдаёт файлы сайта.
2. Вводит почту и пароль → **Auth** проверяет → у браузера появляется токен с `uid`.
3. Портал подписывается на данные курса (`onSnapshot`) → Firestore присылает занятия, оценки, список группы.
4. Преподаватель ставит баллы и жмёт **«Сохранить черновик»** → код из `packages/data/src/teacher.ts` (`saveGrades`) пишет документы `assessmentRecords/{работа}_{студент}` пачками по 8 в одной транзакции.
5. **Security Rules** проверяют каждую запись: это преподаватель этого курса? студент зачислен? баллы от 0 до максимума? `revision` ровно +1? автор и время настоящие? Если хоть что-то не так — запись **отклоняется**.
6. Жмёт **«Опубликовать»** → `publishGrades` меняет `publication: draft → published` у записей и у самой работы.
7. У студента открыт My DU, он подписан на **свои опубликованные** записи → Firestore **сам присылает** изменение (real-time).
8. My DU пересчитывает риск модулем `@aitu/domain` (прямо в браузере) → экран обновляется, сверху появляется **баннер** «Новая оценка: Quiz 2 — 58/100».

### 5.3 Почему риск считается в браузере, а не на сервере

Серверный код (Cloud Functions) в Firebase требует платного тарифа **Blaze** (с картой). Мы на бесплатном **Spark**. Поэтому:
* студент читает **только свои** опубликованные данные и считает риск у себя;
* тот же модуль `@aitu/domain` показывает преподавателю радар группы → оба видят **одно и то же**;
* «подделать» риск можно только на своём экране — данные в базе он изменить не может (Rules не дадут).

## 6. Модель данных (Firestore)

Firestore хранит **документы** внутри **коллекций**. Документ — это набор полей (как JSON). Полная таблица v2 со всеми новыми коллекциями (`joinCodes`, `checkins`, `checkinTokens`, `planState`, `adminLog`, `stats`) — в [DATA_MODEL.md](DATA_MODEL.md).

| Коллекция | Что лежит | Пример ID |
|---|---|---|
| `users/{uid}` | Имя, почта, роль, номер студента, группа | `demo-student-01` |
| `offerings/{id}` | **Курс в конкретной группе**: код, название, семестр, `staffUids[]` (преподаватели), `studentUids[]` (студенты), политика риска | `demo-fall26-math101-se2419` |
| `offerings/{id}/enrollments/{uid}` | Зачисление: имя, номер, группа, статус | |
| `offerings/{id}/sessions/{id}` | Занятие: тип, тема, **аудитория**, время, статус (запланировано / проведено / отменено), опубликована ли посещаемость | `w8-1` |
| `offerings/{id}/attendanceRecords/{занятие}_{студент}` | Отметка: П/О/У/Н, баллы, примечание, `publication`, `revision` | `w8-1_demo-student-01` |
| `offerings/{id}/assessments/{id}` | Оценивание: название, тип, максимум, дедлайн, **регистр** (`period`) и **вес** (`weight`) | `quiz2` |
| `offerings/{id}/assessmentRecords/{работа}_{студент}` | Оценка: сдача, оценено/нет, баллы, **feedback**, `publication`, `revision`, `correction` | `quiz2_demo-student-01` |
| `offerings/{id}/audit/{id}` | Журнал: кто, когда и почему исправил опубликованное (только дописывается) | |

Пример документа оценки:

```json
{
  "assessmentId": "quiz2",
  "studentUid": "demo-student-01",
  "submission": "submitted",
  "gradeState": "graded",
  "points": 58,
  "maxPoints": 100,
  "feedback": "Есть ошибки в вычислениях, разберите задачу 3",
  "publication": "published",
  "revision": 3,
  "updatedBy": "demo-teacher-math",
  "updatedAt": "2026-10-26T05:40:12Z",
  "correction": null
}
```

Ключевые идеи:

* **`publication: draft / published`** — черновик видит только преподаватель; студент и Risk Engine — только опубликованное.
* **`revision`** — номер версии. Каждая запись должна быть ровно +1. Если два преподавателя правят одно и то же, второй получит «конфликт», а не затрёт чужое (оптимистичная блокировка).
* **ID = `{работа}_{студент}`** — повторная отправка не создаёт дубликат, а перезаписывает тот же документ.
* **Регистры (RegMid, RegEnd…) не хранятся** — их каждый раз вычисляет `grading.ts`. Так не бывает рассинхронизации.

Где посмотреть вживую: Firebase Console → **Firestore Database → Data** → `offerings` → курс → `assessmentRecords`.

## 7. Безопасность

| Мера | Как работает | Как показать на защите |
|---|---|---|
| **Пароли** | Хранит и проверяет Firebase Auth (хэширование на стороне Google). В нашей базе паролей нет. | Console → Authentication: видно пользователей, паролей не видно |
| **HTTPS** | Hosting и Firestore работают только по HTTPS | Замок в адресной строке `…web.app` |
| **Права (Security Rules)** | Преподаватель пишет только в свои курсы; студент читает только свои **опубликованные** записи; роли и списки групп клиент менять не может | `npm run check:student`: попытка прочитать чужую оценку и записать себе оценку → **отклонено** |
| **Целостность** | `revision +1`, автор = тот, кто вошёл, время = время сервера, баллы в диапазоне | Попробовать в консоли браузера записать оценку — ошибка `permission-denied` |
| **Исправления** | Изменить опубликованное можно только с причиной; создаётся запись в `audit` | Исправить отметку → портал просит причину → в `audit` новая запись |
| **Секреты** | Ключ сервисного аккаунта (для seed) хранится **вне** проекта и не попадает в git/zip. Web-конфиг (`apiKey`) — не секрет, доступ защищают Rules | `.gitignore` |
| **Только синтетика** | Демо-пароли публичные, поэтому реальных данных в базе нет | — |
| **Роли** | Студент при регистрации может создать только профиль `student` со своей почтой; администратор — только claim в токене | Попробовать в консоли браузера записать себе `role: 'teacher'` → отказ |
| **Вступление в курс** | Только себя, только с активным кодом этого курса, только с подтверждённой почтой | Сменить код у преподавателя → старый код в My DU «не найден» |
| **QR-отметка** | Код проверяется по времени сервера (45 с), одна отметка на студента, студенты не могут прочитать текущий код из базы | Сфотографировать QR, подождать минуту, открыть ссылку → «Код не принят» |
| **Заголовки сайта** | CSP (чужие скрипты не выполнятся), HSTS, запрет встраивания в чужие сайты (`X-Frame-Options: DENY`), `nosniff` | DevTools → Network → любой ответ → Response Headers |
| **Сессия** | Портал выходит сам после 30 минут бездействия | — |
| **Журналы** | `audit` курса и `adminLog` можно только дополнять | Панель администратора → «Журнал» |
| **Резервные копии** | Восстановление — только с компьютера владельца (Admin SDK), из браузера нельзя | «Резервные копии» → блок «Восстановление» |

Подробно — в [SECURITY.md](SECURITY.md).

Как Rules выглядят «по-человечески» (фрагмент):

```
offerings/{курс}/assessmentRecords/{запись}:
  читать:  преподаватель этого курса
           ИЛИ (это моя запись И она опубликована)
  писать:  только преподаватель этого курса,
           студент зачислен, баллы 0…max, revision = старая + 1,
           updatedBy = я, updatedAt = время сервера,
           если меняю опубликованное — обязательна причина
```

### 8.2 Что делает `npm run deploy`

1. `npm run build` — Vite собирает оба приложения в папку `dist/hosting` (портал в корень, My DU в `my-du/`). Это просто статические файлы.

**Почему не GitHub Pages?** Можно и туда (это тоже статические файлы), но Firebase Hosting уже настроен, работает одной командой, с HTTPS и правильной маршрутизацией `/my-du/`. GitHub лучше использовать для **хранения кода** (приватный репозиторий), а не для хостинга.

### 10.2 Ограничения, о которых стоит сказать самим

* **Демо-пароль публичный** → любой может войти в демо-аккаунт и изменить синтетические данные. Лечится `npm run seed -- --yes` (настоящие курсы и студенты при этом не трогаются).
* **QR можно «передать» соседу**, стоящему у двери в те же 45 секунд — как и при обычной перекличке. Защищаемся от отметки «из дома», а итог подтверждает преподаватель.
* **Лимита попыток** ввода кода в правилах нет: это умеют только App Check / Cloud Functions. Перебрать 1 000 000 вариантов за 45 секунд из браузера нереально.
* **Аналитика** читает всю базу, поэтому считается по кнопке, а не при каждом открытии (квота Spark — 50 тыс. чтений в день).

## 11. Шпаргалка для защиты

**«Где у вас сервер?»**
Своего сервера нет: используем Firebase (BaaS). Auth — вход, Firestore — база, Hosting — сайт. Правила доступа в `firestore.rules` выполняет Google при каждом запросе — это наш «бэкенд».

**«Как интерфейс общается с базой?»**
Через Firebase SDK прямо из браузера по HTTPS, с токеном пользователя. Для real-time — подписка `onSnapshot`: база сама присылает изменения.

**«Покажите, где это значение лежит в базе».**
Console → Firestore → `offerings` → `demo-fall26-math101-se2419` → `assessmentRecords` → `quiz2_demo-student-01` → поле `points`.

**«Почему студент не видит черновик?»**
В Rules: студент может читать запись, только если `studentUid == его uid` **и** `publication == 'published'`.

**«Что будет, если два преподавателя изменят одну оценку одновременно?»**
У записи есть `revision`. Rules принимают только `revision = старая + 1`. Второй получит конфликт и увидит, что строку нужно обновить — данные не затираются.

**«Почему риск считается на клиенте?»**
Серверные функции требуют платного тарифа. Расчёт детерминированный и общий для обеих сторон; данные, на которых он основан, клиент изменить не может.

**«Почему “Мало данных”, а не “В норме”?»**
Если данных меньше чем из двух источников, честнее сказать «не знаем», чем успокоить студента.

**«Откуда число 69?»**
RegMid у Армана = 31. Для допуска нужно RegTerm ≥ 50: 0.5 · 31 + 0.5 · RegEnd ≥ 50 → RegEnd ≥ 69.

**«Как пароли защищены?»**
Паролей в нашей базе нет — их хранит Firebase Auth. Сайт работает только по HTTPS.

**«Что будет, если упадёт интернет?»**
Показываем демо-видео из Assignment 4 или запускаем `npm run demo:offline` — те же экраны с данными в памяти браузера.

**«Как студент попадает в курс?»**
Регистрируется сам в My DU (корпоративная почта), подтверждает почту и вводит код курса, который дал преподаватель (или сканирует QR на первой лекции). Правила проверяют, что он добавил только себя и что код действующий и именно этого курса.

**«Почему преподаватель не регистрируется сам?»**
Иначе любой студент стал бы «преподавателем». Преподавателя создаёт администратор, при первом входе пароль нужно сменить.

**«Как стать администратором?»**
Только командой `npm run make-admin` с компьютера владельца проекта: она ставит claim `admin` в токен через Admin SDK. В браузере такой кнопки нет, а поле `role` в документе на права не влияет.

**«Как работает QR у двери? Это IoT?»**
Планшет у входа — «датчик»: каждые 20 секунд пишет в базу новый код и время сервера. Студент сканирует QR, My DU отправляет код; правило принимает его, только если код текущий или предыдущий и прошло меньше 45 секунд по часам сервера. Фото QR из чата через минуту не работает. Без телефонов показываем `npm run iot:simulate`.

**«Что будет, если базу случайно испортят?»**
Есть резервные копии: из панели администратора, `npm run backup` и каждую ночь в GitHub Actions. Восстановление — `npm run restore` с пробным прогоном. Из браузера восстановить нельзя специально: это слишком опасная кнопка.

**«Можно ли зарегистрироваться на чужую почту?»**
Зарегистрироваться можно, но в курс не попасть: вступление требует подтверждённую почту, а письмо со ссылкой придёт настоящему владельцу ящика.

**«Данные реальные?»**
Нет, синтетические: сгенерированы `scripts/seed-data.ts` (50 студентов, 5 курсов, разные «траектории»). Графики показывают, что метод работает, а не что делают реальные студенты.
